# 迷宫保活 · 云函数实现（Milky Way Idle 测试服）

一个**零依赖**的 Node.js 云函数：定时连上游戏的 WebSocket，检查迷宫状态，需要时自动「开局 / 启动房间 / 到停止层后结束并重开 / 补入场券」。

已部署在华为云 FunctionGraph（华南-广州，Node.js 18.15）实测运行。

## 1. 它做什么

每次触发（建议 15 分钟）执行一轮「连接 → 读状态 → 决策 → 发 0~3 个协议包 → 断开」：

| 观察到的情况 | 动作 |
|---|---|
| 有一轮迷宫，且角色正在房间里干活 | 什么都不做 |
| 有一轮迷宫，角色空闲，**未到**停止层 | 启动当前房间（`new_character_action`） |
| 有一轮迷宫，角色空闲，**已到**停止层 | 结束本轮（`escape_labyrinth`），随后在同一连接里开新一轮并启动房间 |
| 没有在跑的一轮，有入场券 | 开一轮（`start_labyrinth`）+ 启动房间 |
| 没有在跑的一轮，没有入场券 | 补票（`force_refill_labyrinth_entries`），服务端按冷却裁决 |

停止层 = `min(characterSetting.labyrinthFullAutoFloor, characterInfo.labyrinthFullAutoLevel)`，
也就是「游戏设置里自动化到第几层」和「已解锁的自动层上限」取较小值。

角色在房间里怎么打、走哪条路、用什么消耗品，**全部交给游戏自带的自动化**，本函数只负责「让它一直真在跑」。

## 2. 为什么不用浏览器自动化

游戏客户端会检测点击：**点击后 100 毫秒内发出的消息会被打上 `isAuto: true`，服务端静默丢弃**。

所以正确做法不是模拟点击，而是直接走 WebSocket 协议。本实现用 `node:tls` 手写了 WebSocket 客户端（`wsclient.mjs`），不依赖任何 npm 包，也不需要浏览器、无头内核或 CDP。

### 鉴权实测结论

| 项 | 结论 |
|---|---|
| 必需的凭据 | **只有一个** `accessToken` Cookie |
| 握手 URL 的 `hash` 参数 | **必须存在、长度要像 20 位**，但**值不校验**（写随机串也能连上） |
| `Origin` / `User-Agent` | **不需要**，可以完全不发 |
| 假令牌 | 握手能成功（101），但收不到任何下行消息，服务端随即断开 |
| `gameVersion` / `versionTimestamp` / `marketValuesVersion` | 不能删，按抓到的原值保留 |

## 3. 部署到华为云 FunctionGraph

### 3.1 准备代码包

```bash
# 生成单文件版（控制台在线编辑器只有一个 index.js，合并成一个文件最省事）
node build-cjs.mjs
# 产物：dist-single/index.js（CommonJS 单文件）、dist-cjs/（多文件 CJS）
```

也可以直接把 `index.js` + `wsclient.mjs` + `package.json` 压成 zip 上传（ESM 版）。

### 3.2 创建函数

| 配置项 | 值 |
|---|---|
| 函数类型 | 事件函数 |
| 运行时 | Node.js 18.15（≥16 均可） |
| 函数执行入口 | `index.handler` |
| 内存 | 128 MB（够用，实测峰值 ~81 MB） |
| 超时时间 | **60 秒**（默认 3 秒完全不够：握手就要 1~2 秒） |
| 委托 | 不需要（不访问任何其他云服务） |
| 函数访问公网 | 保持开启（默认开启） |

### 3.3 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `MWI_TOKEN` | ✅ | `accessToken` Cookie 的**值**（不含 `accessToken=` 前缀） |
| `MWI_URL` | ✅ | 完整 WebSocket 地址，见下文 |
| `MWI_LIVE` | — | `0` = 只读模式（只判定不发包）；不设或其他值 = 真发包 |
| `MWI_RESTART_AT_CAP` | — | `0` = 到停止层不自动重开（默认重开） |
| `MWI_INIT_TIMEOUT_MS` | — | 等待角色数据的超时，默认 12000 |

> ⚠️ **不要勾选「加密参数值」**。实测勾选后函数里 `process.env` 完全看不到这些键（缺 KMS 解密权限），表现为"环境变量没生效"。取消加密后立即恢复正常。

### 3.4 定时触发器

在「设置 → 触发器 → 创建触发器」中：

1. 触发器类型选 **定时触发器 (TIMER)**（下拉默认是 `API Connect (APIC)`，要手动改）
2. 创建方式选 **固定频率**
3. 填 `15`，单位选 **分钟**

> 固定频率是从**创建时刻**起算的，不对齐整刻。例如 `23:23:39` 创建，触发点为
> `00:08:39 / 00:23:39 / 00:38:39 / 00:53:39 …`。
> 如果希望固定落在 `:00 :15 :30 :45`，可以改用 cron 表达式 `0 */15 * * * *`。
> 华为云的 cron 按 **UTC** 计时，但与北京相差整 8 小时，所以刻钟相位在两个时区是一致的。
> 若界面支持 `@every 15m` 写法，也等价。

### 3.5 首次验证

先不设 `MWI_LIVE`（或设成 `0`），手动触发一次，返回里应该看到：

```json
{ "ok": true, "live": false, "steps": ["handshake ok"],
  "before": { "runActive": true, "floor": 9, "actionRunning": true, "cap": 12, "tickets": 4 },
  "plan": [] }
```

`before` 里有 `floor` / `tickets` 就说明读到了真实状态。确认无误后再设 `MWI_LIVE=1`。

每次调用都会打印一行 `[mwi] {...}` 到日志，`plan` 是这一轮打算做什么，`after` 是执行后的状态。

## 4. 如何获取 `MWI_TOKEN` 与 `MWI_URL`

1. 浏览器登录测试服并进入游戏。
2. 打开开发者工具 → **Application / 存储 → Cookies** → 找到 `milkywayidle.com` 域下的 **`accessToken`**，复制它的值。
3. 切到 **Network → WS**，点开那条 WebSocket 连接，复制完整地址，形如：

```
wss://api-test.milkywayidle.com/ws?hash=<20位>&characterId=<角色ID>&gameVersion=<版本>&versionTimestamp=<数字>&marketValuesVersion=<数字>&lang=zh-CN&isSteam=0
```

> **令牌会过期**（`accessToken` 是 JWT）。过期后日志里出现
> `未收到 init_character_data 且无任何下行数据`，此时只需重新复制一次 `accessToken`、更新环境变量，**不用改代码、不用重新部署**。

## 5. 实测过程中踩到的坑（重要）

### 5.1 「影子期」—— 两次连接间隔太近会拿不到角色数据

客户端断开后，**服务端仍会保留该角色会话约 1~3 分钟**。在这个窗口内新建的连接能握手、能收到全局广播 `market_item_values_updated`，但**收不到 `init_character_data`**。

后果：函数安静地失败一次，`ok: false`，错误信息会提示这个原因。

规避：
- 定时触发间隔保持 **≥ 5 分钟**（15 分钟最稳）；
- 手动调试时，两次连接之间至少隔 **4 分钟**，否则必然误报"角色已被占用"。

### 5.2 角色正在别处登录时不会互相踢下线

角色已被别的会话占用时，本函数拿不到角色数据就退出，**不会把对方顶下线**，对方也不受影响。因此"你在玩游戏"和"云端定时跑"可以共存，只是云端那几次会空跑。

确实收到 `close_session` 或连接被服务端关闭时才需要怀疑令牌失效。

### 5.3 「有一轮迷宫」不等于「迷宫在跑」

`start_labyrinth` 只创建一轮并把层数置 1，**角色仍然空闲**。必须紧接着发一条房间动作包，游戏自带的自动化才会接手。少了这一步，角色会一直站在第 1 层不动。

### 5.4 到达停止层后不能继续补房间

游戏自动化跑到 `labyrinthFullAutoFloor` 就停，此时状态是 `isActive=true` + `actionRunning=false`。如果这时继续发房间动作，角色会永远停在同一层反复发包。正确做法是 `escape_labyrinth` 结束本轮再开新的。

## 6. 成本

华为云 FunctionGraph 免费额度（每月，主/子账号共用）：100 万次请求 + 400,000 GB-秒。

按本实现实测数据估算（128 MB、单次约 7 秒、每 15 分钟一次）：

| 项目 | 用量 | 免费额度 | 占用 |
|---|---|---|---|
| 请求次数 | ≈ 2,900 次/月 | 1,000,000 | **0.3%** |
| 计量时间 | ≈ 2,700 GB-秒/月 | 400,000 GB-秒 | **0.7%** |

即使改成每 5 分钟触发一次，也只用约 1.6%。**注意不要开启「预留实例」**——那部分不计入免费额度，是持续计费的；另外日志服务 LTS 单独计费，建议设个保留期。

## 7. 目录结构

```
.
├─ index.js          入口与状态机（handler + 本地 CLI）
├─ wsclient.mjs      零依赖 WebSocket 客户端（node:tls 手写握手 + 帧编解码）
├─ build-cjs.mjs     ESM → CommonJS / 单文件构建
└─ package.json      type: module，无任何 dependencies
```

本地调试（需要一份包含凭据的 `handshake.json`，不要提交）：

```bash
node index.js --handshake handshake.json          # 只读模式
node index.js --handshake handshake.json --live   # 真发包
```

## 8. 不做什么

- 不做自动登录、不处理验证码（令牌需人工获取并续期）
- 不处理迷宫内的走位、路径规划、消耗品使用（交给游戏自带自动化）
- 不做多账号 / 多角色
- 不做事件级的动态调度（定时触发是周期性的，无法锚定"上次结束 + 100 分钟"这种业务时间）
